# Design

## Context

동기와 범위는 proposal.md를 따른다. 현재 홈·폼·상세는 TDS Button/Top과 기존 CSS를 쓰고 `apps-in-toss.config.ts`의 `#09635B`를 브랜드 색으로 사용한다. 홈은 요약·필터·활성 목록·보관 목록·빈 상태와 배너를, 폼은 오류·저장 잠금, 상세는 상태 변경과 삭제 확인을 제공한다. 콘솔 테스트 버전 `20261027-1`의 주요 흐름은 사용자가 Android에서 정상 확인했지만, 그 이후 디자인은 브라우저에서만 검증했다.

## Goals / Non-Goals

**Goals:** 화면별 위계와 상태별 접근성을 실제 화면으로 확인하고 필요한 최소 수정만 정한다. 플랫폼 내비게이션과 자체 버튼의 중복 여부를 실기기 근거로 판정한다.

**Non-Goals:** 새 라우터, 상태 관리, 색상 토큰 체계, 데이터 모델, SDK 도입이나 구독 관리 기능 변경은 하지 않는다. 광고 수익 설정·실제 광고 노출 검증 및 콘솔 심사는 기존 MVP 6단계가 담당한다.

## Decisions

### 현재 구현을 기준으로 화면별 보완

기존 로고 및 청록색, TDS provider·버튼·현재 컴포넌트를 재사용한다. 새 화면을 전면 재구성하기보다 홈의 요약/목록, 폼의 입력/오류/동작, 상세의 상태/확인 조작을 상태별로 확인해 실제 발견된 문제만 고친다. 새 디자인 시스템을 도입하는 방식은 현재 범위에 비해 불필요하다.

### 브라우저와 실제 토스 앱 검증을 분리

Chrome mock에서 320px과 일반 너비, 긴 이름·큰 금액, 각 상태 및 터치 영역·텍스트·스크롤을 확인한다. Android에서는 키보드·safe area·플랫폼 뒤로가기·광고/CTA 간격을 확인한다. 브라우저 결과나 과거 번들 결과를 새 디자인의 기기 통과로 대체하지 않는다. 배너 실노출과 외부 광고 상태는 MVP 6.2에서 판정한다.

### 뒤로가기 중복은 플랫폼 실제 표시를 확인

`SubscriptionDetail`의 자체 돌아가기와 플랫폼 버튼이 동시에 보이는지 Android 토스 앱에서 확인한다. 중복이면 공식 가이드에 맞춰 자체 버튼을 제거하거나 플랫폼 상태에 맞게 표시하고, 브라우저 및 네이티브 복귀 경로를 함께 검증한다. 동작 자체를 재설계하지 않는다. 실기기 확인이 불가능하면 완료로 판단하지 않는다.

### 검증 기록의 정본

실기기 세부 결과는 기존 `subscription-radar-mvp/device-validation.md`와 6.3~6.5 체크리스트에 연결한다. 동일 환경·버전·조건에서 수행한 검증은 양쪽 작업이 같은 근거를 공유한다. 각 체크박스는 해당 작업의 전체 완료 조건을 충족한 경우에만 완료하며, 광고·실기기·출시 등 남은 조건이 있으면 부분 검증만으로 완료하지 않는다. 기존 기록에 미커밋 사용자 변경이 있으면 작업 전 백업 정책을 따른다.

## Risks / Trade-offs

- [TDS와 자체 CSS의 스타일 차이] → 기존 컴포넌트를 우선하고 실제 렌더링에서 대비와 터치 크기를 확인한다.
- [플랫폼 뒤로가기의 환경 차이] → 브라우저 이벤트 테스트와 Android 시스템·토스 버튼 실측을 분리한다.
- [실기기 또는 콘솔 접근 불가] → 해당 체크를 미완료로 남기고 나머지 로컬 검증 결과만 기록한다.
- [진행 중인 MVP와 중복] → 원본 기능·광고·출시 검증은 MVP의 기존 작업을 참조하고 이번 변경은 디자인 관련 증거만 다룬다.

## Migration Plan

저장 스키마와 사용자 데이터 마이그레이션은 없다. 변경 후 기존 테스트·lint·타입 검사·빌드와 브라우저 검증을 수행한다. 실기기 후보 업로드와 공개 커밋·푸시는 별도 사용자 승인에 따른다. 되돌릴 때는 승인된 Git 기준으로 변경 파일을 복원하되 기기 데이터는 삭제하지 않는다.
