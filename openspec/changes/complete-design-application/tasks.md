# Tasks

## 1. 화면 디자인과 상태

- [ ] 1.1 현재 홈의 요약·필터·활성 및 보관 목록·빈 상태를 320px과 일반 너비에서 점검하고 실제 발견된 위계·줄바꿈·터치 문제만 수정한다. 브라우저에서 긴 이름·큰 금액과 각 필터 상태를 확인한다.
- [ ] 1.2 등록·수정 폼의 입력, 레이블, 입력 오류, 저장 중과 실패 상태의 위계 및 취소 접근성을 점검하고 필요한 부분만 수정한다. UI 테스트로 오류 연결·draft 보존·저장 잠금을 확인한다.
- [ ] 1.3 상세의 이름·금액·상태와 삭제 확인의 위계 및 실제 구독 해지 안내를 점검하고 필요한 부분만 수정한다. 상태 변경과 삭제 확인·취소 UI 테스트를 통과시킨다.

## 2. 접근성과 플랫폼 연결

- [ ] 2.1 화면별 최소 터치 44px, 본문 15px, 한국어 줄바꿈, 텍스트 대비, 하단 safe area 및 광고와 CTA 간격을 브라우저에서 점검하고 문제를 수정한다. 320px의 가로 넘침과 스크롤 접근을 확인한다.
- [ ] 2.2 Android 토스 앱에서 상세의 자체 돌아가기와 플랫폼 뒤로가기 동시 노출 여부를 확인한다. 중복이면 공식 가이드에 맞게 필요한 표시를 수정하고 내부 화면의 시스템·토스 뒤로가기가 한 번에 한 화면 이동하는지 검증한다.
- [ ] 2.3 S26 Ultra 등 실제 Android 토스 앱에서 최신 디자인 번들의 키보드, 긴 이름·큰 금액, safe area와 화면 전환을 확인하고 기기·OS·토스 앱 버전·번들·실제 결과를 기존 MVP 기기 검증 기록에 남긴다. 실행할 수 없으면 미완료로 둔다.

## 3. 통합 검증

- [ ] 3.1 전체 테스트, lint, typecheck, build 및 diff 검사를 실행하고 기존 CRUD·저장 실패·필터 동작이 유지되는지 확인한다. 실패와 미검증 항목은 결과에 기록한다.
- [ ] 3.2 브라우저에서 등록→수정→상태 변경→삭제 취소·삭제를 검증하고 Android 결과를 기존 `subscription-radar-mvp` 6.2~6.5의 검증 기록과 대조한다. 같은 환경·버전·조건에서 수행한 동일 검증은 증거를 공유하고, 각 작업의 전체 완료 조건이 충족되면 양쪽 작업을 모두 완료 처리한다. 일부 조건만 충족하거나 광고·실기기·출시 확인이 남은 작업은 완료하지 않는다.
