## 6. 콘솔 준비·Android 실기기·출시 준비 판정

이 단계는 외부 준비/별도 실행 요청이 필요하다. 콘솔 값·기기·권한 미확보 시 미완료로 남기고 진행을 막는 조건을 기록한다. 계획 작성 또는 로컬 구현 완료만으로 체크하지 않는다.

- [x] 6.1 사용자 제공 실제 appName 및 콘솔 표시명을 확인해 임시값을 교체하고 최종 번들 식별자와 콘솔 값의 일치를 확인한다. 테스트 배포가 요청되면 그 범위에서 번들 업로드와 테스트 링크 확보까지 확인한다.
- [ ] 6.2 발급·정산/사업자·광고 승인 상태를 확인하고 사용 가능한 광고 그룹으로 테스트한다. 지원 환경에서 실제 배너 노출·해제, 미지원/No Fill에서 CRUD 유지 증거를 남긴다. 미발급은 완료로 처리하지 않는다.
- [ ] 6.3 Android 토스 앱에서 첫 등록·수정·삭제/취소·상태 변경·종료/재진입·foreground·저장 데이터 표시를 검증하고 기기·OS·토스 앱 버전·번들·결과를 기록한다(T-10/14/16).
- [ ] 6.4 Android에서 시스템/토스 뒤로가기, 홈 종료, 키보드, 긴 이름·큰 금액·작은 화면, safe area와 광고/CTA 간격을 검증한다. 네트워크가 끊겨도 진입 가능한 상태에서 기존 기록이 보이는지 확인하고 검증한 범위를 기록한다.
- [ ] 6.5 검증 시점의 공식 비게임 출시 체크리스트 및 실제 저장/수집 방식에 맞는 데이터 안내를 점검하고 근거를 남긴다. 기획서 DoD와 대조해 통과/대기/미검증을 구분하고 iOS 미실행은 명시한다. 필수 실기기 실패 또는 대기 작업이 있으면 전체 MVP 완료로 판정하지 않는다.

## Workflow follow-up

- 구현은 사용자의 별도 apply 요청으로 시작한다. 기존 미커밋 파일의 수정 전 백업 방식은 사용자 정책에 맞춰 확인한다.
- 기획서 원본과 기존 사용자 변경을 보존한다. 공개 커밋·푸시·심사 신청·출시는 별도 승인 후 수행한다.
- 필수 작업과 검증이 끝난 뒤 별도 archive 요청으로 main specs 반영·보관을 진행한다.
